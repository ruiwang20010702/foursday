# 十分钟上岗与体验验收

Foursday 的普通用户不需要理解 Profile、Registry、Shadow、Checkpoint、generation 或 acceptance。默认体验只回答四件事：是否已经上岗、谁在负责、做到哪一步、是否需要用户。

## 1. 入口分工

| 入口 | 用户用途 | 默认展示 |
|---|---|---|
| 钉钉 | 交代工作、补充信息、接收结果 | “好的”责任标记、必要的接单说明、澄清和最终结果 |
| Codex／Claude 插件 | 配置和深度操作 | 安装、项目、权限、任务详情、诊断与恢复 |
| 桌宠 | 随时了解工作状态 | AI 负责、需要我、最近完成、一个推荐动作 |
| 本地只读页面 | 桌宠不可用时应急诊断 | 与桌宠同源的只读状态；不进入普通用户主流程 |

## 2. 一键向导

```bash
foursday setup
```

默认只生成预览；确认后使用 `foursday setup --apply`。向导自动检测 Node、Git、Codex 和 DWS，读取 DWS 已登录账号、Codex 已保存项目与个人 gbrain 可用性，生成私有项目注册表，安装 Foursday Profile，启动发送关闭的试用模式，并执行一次真实 Codex 只读验证。

只有无法可靠推断时才询问，最多两次：

1. 多个钉钉账号时选择本次使用的账号；
2. 选择允许工作的项目根目录；
试用模式不是第三个问题：setup始终停在“不会自动回复”，是否正式上岗只能在完成验收后单独决定。

向导按步骤保存不含凭据的恢复状态；失败后再次执行会从第一个未完成步骤继续。它不得自动激活真实发送、复制现有联系人权限、写入 gbrain、部署生产或把秘密写进命令输出。

## 3. 用户状态

| 用户文案 | 含义 |
|---|---|
| 试用中，不会自动回复 | 已安装并可验证，真实发送关闭 |
| 已上岗 | 消息入口、工作循环和发送边界正常 |
| 正在同步新消息 | 正在补齐消息，已有任务可以继续 |
| 正在后台处理 | AI 已接单，任务可跨会话继续 |
| 需要你 | 缺少业务信息、需要高风险授权或等待验收 |
| 你已接管沟通 | AI 停止对外回复，但可继续整理证据 |
| 任务已由你接管 | AI 停止该任务 |
| 自动回复已暂停 | 无法确认发送结果，后续回复已停止 |

技术字段只在“设置与系统诊断 → 技术详情”中出现。

## 4. 等待体验

| 类型 | 判断 | 对外行为 |
|---|---|---|
| 即时任务 | 预计并实际在 15 秒内完成 | 贴“好的”，直接回复结果，不额外发送接单套话 |
| 普通任务 | 超过 15 秒但不需要跨重启或外部等待 | 贴“好的”；15 秒后仍未完成时只发送一次自然接单说明；在当前会话继续并回复结果 |
| 长任务 | 多步骤、外部等待、长运行工具或需要跨重启 | 贴“好的”；说明预期交付物；进入耐久后台；只在需要人、被阻塞、阶段交付和最终完成时更新 |

Codex 先作语义判断，运行时只根据真实耗时、工具活动和外部等待进行纠偏。程序不得用业务关键词清单替代 Codex。

## 5. 错误恢复

每个异常只显示一个当前最优动作：

| 异常 | 推荐动作 |
|---|---|
| DWS 未登录 | 打开钉钉登录 |
| Codex 未登录 | 打开 Codex 认证 |
| 项目未识别 | 让 Codex 继续判断；只有业务含义会改变结果时才选择项目 |
| gbrain 暂不可用 | 使用当前项目继续，稍后自动补充历史背景 |
| 发送结果未知 | 保持暂停并检查钉钉 |
| 工作区无权限 | 选择允许访问的项目目录 |
| 测试失败 | 查看失败摘要，让 AI 继续修复 |

共享文档权限任务必须先做ACL只读核验。已经具备所需权限时直接显示“权限已具备”，不进入“需要我”；只有确认缺少权限时才要求所有者决定是否授权。ACL读取失败显示“暂时无法核验”，不能显示“尚未授权”。`shared_link`只允许在读取消息内链接的当前Turn短暂出现；Codex选定项目后，桌宠立即按真实项目名称分组，并提示下一Turn进入该项目。

## 6. 指标与30项真实任务

| 指标 | 目标 |
|---|---:|
| 首次安装成功时间 | ≤10分钟 |
| 安装人工输入 | ≤3次 |
| 消息发现 P95 | ≤10秒 |
| Foursday检查启动→检测完成 P95 | ≤10秒 |
| 普通／长任务接单 P95 | ≤15秒 |
| 即时任务首次有效回复 P50 | ≤30秒 |
| 当前责任人理解正确率 | ≥90% |
| 重复发送率 | 0 |
| 人工接管后抢答率 | 0 |
| 真实任务完成率 | ≥90% |
| 桌宠展开稳定时间 | ≤300ms |

延迟必须同时报告四条口径：全量发现P95、`dws_event|filesystem`实时发现P95、`fallback|startup|manual|unknown`补偿发现P95、Foursday检查启动到DWS读取实际完成的内部P95。实时分桶和内部耗时不能替代全量指标；上游事件到达慢、补偿链路超时都必须继续可见。`detectedAt`只能在DWS读取完成后记录，禁止用检查开始时间低估耗时。Shadow入口为每个处理批次生成不含正文的`workItemHash`；它只能帮助定位待复核样本，不能自动证明一项业务任务完成。正式任务数只统计经过终态人工复核并写入`task_result`的私有`taskHash`；旧证据中的`conversationHash`只能显示历史会话覆盖量，不得计入30项门槛、反推联系人或把一次Codex Turn完成视为业务任务完成。

运行：

```bash
npm run experience:record -- \
  --observation /absolute/private/observation.json \
  --evidence /absolute/private/experience.jsonl

npm run experience:verify -- \
  --evidence /absolute/private/experience.jsonl \
  --output /absolute/private/experience-report.json
```

观察文件只允许固定指标字段和已有的隐私安全哈希；记录命令派生稳定任务哈希、拒绝重复任务并一次性追加完整事件组。证据文件每行只保存任务哈希、时间点、响应类型、责任判断和通过／失败结果，不保存聊天正文、人员身份、绝对项目路径、命令、凭据或思维链。少于30项经过终态复核的任务时，报告必须显示“样本不足”，不能宣称通过。
