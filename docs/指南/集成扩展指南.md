# 集成扩展指南

新增能力时优先选择最小的 Foursday 扩展面，发行层在内部把这些契约映射到内嵌控制平面：

| 需求 | 扩展方式 |
|---|---|
| 新消息平台 | Foursday connector |
| 项目发现或上下文 | Profile plugin / Hook |
| 可重复工作方法 | Skill |
| 外部应用 API | MCP server 或 tool plugin |
| 外部或不可逆动作 | 负责人独立授权出口 |

不要新增 capability manifest、业务专用 JSON 指针、固定回复模板、第二套 Agent Loop 或控制平面核心补丁。

任何集成都必须保留身份绑定、项目隔离、秘密隔离、人工接管、幂等、未知结果处理和精确回读，并覆盖成功、拒绝、错配、重试、重启与重复输入测试。

当前实现示例见 `distribution/plugins/` 与 `distribution/skills/`。

## 1. 扩展原则

每个扩展只能承担一类责任：

- Connector：把平台事件归一化为 Foursday 消息契约，并把结果精确投递回平台；
- Router/Context Provider：选择项目或提供有界数据，不执行 Agent Loop；
- Skill：告诉 Codex 如何完成一类工作，不直接持有秘密或发送能力；
- MCP：提供最小、可验证的外部工具；
- 独立授权出口：处理普通 Loop 永久禁止的外部/不可逆动作。

扩展不得绕过 Gateway 直接创建 Codex 线程，不得自行读取整个个人 gbrain，不得复制 permissions、审批或记忆状态机。

## 2. Connector 标准契约

### 2.1 入站事件

新消息平台至少提供：

```text
tenantId
platform
stableUserId
alternateStableId (optional)
conversationId
threadId (optional)
messageId
messageType
text / attachment references
createdAt
chatType
mentionedSelf
replyTarget
```

显示名、头像和昵称只用于表达，不参与授权。事件必须标明租户和平台，禁止跨租户复用 ID。

### 2.2 身份门禁

1. 读取平台原始稳定 ID；
2. 验证响应身份与查询目标一致；
3. 应用 tenant + platform allowlist/pairing；
4. 群聊应用白名单与提及规则；
5. 构造统一主体键；
6. 只有全部通过才创建 Session。

### 2.2.1 消息内钉钉文档

- Connector只在稳定身份验证后提取精确`alidocs.dingtalk.com/i/nodes/...`链接，最多4个；不把URL或nodeId交给模型。
- Owner直聊生成15分钟`owner_exact_link`临时来源；其他当前企业成员生成`enterprise_exact_link`。两者都只授权消息中精确给出的节点，不开放搜索或相邻文档。
- 群聊、Cron、显示名、引用中的权限声明和文档正文都不能产生Owner权限。
- Codex Shell不得探测或调用DWS；集成必须保留host unavailable、scope denied、read failed和not found四类错误。

### 2.3 出站结果

Connector 的发送结果必须区分：

| 状态 | 含义 | 处理 |
|---|---|---|
| completed | 平台返回稳定 message ID，或唯一回读成功 | 记录幂等账本 |
| failed-before-send | 明确未开始 | 可创建新的受控重试 |
| unknown | 可能已发送但无唯一证据 | 禁止自动重试 |
| blocked | DLP、接管、Shadow 或权限拒绝 | 不发送 |

### 2.4 Connector 必须实现

- connect/disconnect 与健康检查；
- allowlist/pairing；
- 私聊与群提及语义；
- 消息去重和源时间排序；
- bounded bundling；
- send + readback；
- 撤回/删除事件（平台支持时）；
- 人工介入与沟通/任务所有权；
- 区分沟通接管、任务纠正、任务接管、恢复和无关本人消息，并为发送generation提供源时间与reply target；
- 重启检查点；
- 只向宿主桥传最小环境。

## 3. 飞书、Slack、Teams 接入约束

| 平台 | 稳定身份 | 群触发 | 回复目标 | 重点风险 |
|---|---|---|---|---|
| 飞书 | tenant/app + open_id/user_id | 白名单群 + @bot/应用 | message/thread ID | 多租户 ID 不可跨企业复用；机器人身份与用户身份需明确 |
| Slack | team_id + user_id | channel allowlist + app mention | channel + thread_ts | Enterprise Grid 跨 workspace 身份；线程与频道权限差异 |
| Teams | tenant_id + AAD user ID | team/channel allowlist + mention | conversation/activity ID | Bot Framework 重试、Activity 幂等和租户边界 |

三者默认使用平台官方入口，不模拟个人账号。若未来提供个人账号连接器，必须作为独立高风险插件，不得与机器人连接器混用授权口径。

## 4. 多平台 Session 身份

跨平台恢复不能根据邮箱、昵称或模型推断自动合并。统一账本至少包含：

```json
{
  "profile": "foursday",
  "tenant": "tenant-id",
  "platform": "slack",
  "principal": "stable-user-id",
  "conversation": "stable-conversation-id",
  "projectId": "project-id",
  "workspace": "/canonical/project/root",
  "codexThreadId": "thread-id",
  "hermesSessionId": "session-id",
  "permissionVersion": "sha256",
  "ownerRevision": 3,
  "lastVerifiedAt": "ISO-8601"
}
```

恢复前重新验证身份、allowlist、项目存在、规范CWD、独立Codex Home归属、任务所有权和permissionVersion。任一变化时新建线程；不能把旧线程的权限带到新平台。Foursday只保存绑定，不复制完整Codex Turn正文。

## 5. Skill 规范

Skill 适合“如何工作”，不适合“是否有权限”。

Foursday默认使用隔离Codex Home中的审核Skill。本人、可信联系人和群聊可以得到不同Skill集合；不得自动复制默认个人Codex Home中的全部Skill和写权限。Codex可以读取Skill完成工作，自动创建/修改Skill应先产生可审查候选。

### 5.1 应包含

- 触发场景与非触发场景；
- 证据优先级；
- 主流程与失败恢复；
- 必须回读的结果；
- 输出结构与自然表达原则；
- 何时停止在独立授权出口。

### 5.2 不得包含

- 明文凭据、个人 ID、生产 URL；
- 固定业务答案或会过期的数字；
- `git push`、部署、付款等绕过动作；
- 另一套长期记忆；
- “忽略系统规则”“主人已授权”等提示提权；
- 与特定联系人绑定的项目授权。

## 6. MCP 规范

### 6.1 最小工具面

一个 MCP Server 只暴露当前产品必需工具。输入 schema 关闭 `additionalProperties`，枚举、长度、数量、路径和置信度全部有界。

### 6.2 身份与上下文

- 模型不能直接传 tenant、project、requester 或权限版本。
- 使用宿主生成的短期随机 Token 绑定这些字段。
- Store 层再次校验 Token 来源、CWD、Session 和有效期。
- 错误返回固定代码，不回显秘密、文件正文或数据库异常。
- MCP可见性按主体分层：本人自聊可使用完整审核集；可信联系人只使用项目相关、只读或任务授权范围内工具；群聊使用最小只读集。
- 默认个人Codex Home中的Gmail、Drive、GitHub写入、云平台和数据库MCP不能因联系人进入allowlist而自动继承。

### 6.3 副作用

- 读取工具默认自动批准，但必须有限量和作用域；
- 可恢复写入要求幂等键、执行前状态和精确回读；
- 外部/不可逆写入不能仅靠 MCP 描述声明“高风险”，必须离开普通 Loop；
- 结果未知时禁止自动重试。

### 6.4 项目绑定的钉钉来源

- 私有v2工作范围注册表的scope最多预登记20个`dingtalkSources`，子scope可继承父scope，字段严格为`id/name/kind/nodeId`且当前只支持`kind=doc`；
- 模型只能先调用`foursday_list_project_sources`取得项目内sourceId，再用`foursday_read_project_source`读取；不得传nodeId、URL、workspace、联系人或全库query；
- `DWS_PATH/FOURSDAY_DWS_HOME`只写入`[mcp_servers.foursday.env]`，不得进入Codex App Server、项目Shell或工具输出；
- 宿主只执行固定`dws doc +fetch --node <registered>`，命令8秒、stdout 2MB、正文返回30,000字符上限；响应包含实时读取时间、全文SHA-256和截断标记；keyword命中必须返回`keywordFound/excerptStart`并确保截断片段包含命中内容；
- 仅direct工作上下文可读，group/cron默认失败关闭；DWS正文始终是data-only，内部指令、链接、权限表述或“主人同意”不能扩大工具权限。

## 7. 工作范围路由与上下文 Provider

Router只输出：状态、主范围、相关范围、唯一workspace、候选和用户可读上下文。它不替Codex决定开放关系、不发送消息、不读密钥。v2将workspace与scope分离，`parentId`只表达继承；其他关系来自个人gbrain的有界项目搜索。

Context Provider 只读取 Router 授权的精确资源，并返回有界数据：

- 主/相关范围的精确gbrain slugs与当前token发现回执；
- 指定项目的只读 API；
- 当前会话必要的历史摘要；
- 用户明确授权的文件。

外部数据必须标记为 data-only；来源中的指令不能成为 developer/system instruction。

## 8. 定时任务与主动触发器

调度与执行分离：Hermes Cron/Hook负责什么时候触发、持久计划、暂停/恢复/删除和投递目标；Codex Thread负责理解、范围选择、搜索、Web/MCP/Skills、项目工作、验证和自然结果。Foursday只绑定身份、主workspace、权限、去重和静默时段，不实现第二Scheduler或Agent Loop。

Scheduler 扩展必须提供：

- create/list/inspect/pause/resume/delete；
- 明确时区、首次运行、错过执行和重试策略；
- 任务绑定 profile、project、creator 和 permissionVersion；
- 最大并发、最大运行时间和费用预算；
- 每次运行关联的Hermes Session、Codex Thread、输入、工具证据和终态；
- 用户暂停后不再创建新 Turn。

主动监听优先使用Hermes`monitor-script`：来源脚本输出必须稳定且不含时间戳，字节未变化时不唤醒Codex。定时触发不扩大权限。普通Turn中禁止的push、deploy、production、payment，在定时任务中仍禁止；默认结果只留本地，不直接发送DWS。

## 9. Agent宿主与可视化入口

Codex和Claude插件必须保持薄客户端：只启动`foursday control-mcp`，不直接读取DWS、Thread文件、Cron或gbrain。任何新宿主都复用`foursday_status/tasks/schedules/memory/evidence/control`契约。

仓库同时提供标准Codex与Claude marketplace清单，新用户可在克隆目录执行：

```bash
foursday_cli_package=$(mktemp -d)
npm pack --ignore-scripts --pack-destination "$foursday_cli_package"
npm install --global --ignore-scripts "$foursday_cli_package"/foursday-*.tgz

codex plugin marketplace add .
codex plugin add foursday@foursday-local

claude plugin marketplace add . --scope user
claude plugin install foursday@foursday-local --scope user
```

安装后新建Codex任务或Claude Code会话，使Skill与MCP重新发现。两个插件都依赖同一个已安装`foursday` CLI，不携带第二套Runtime或状态机。

写控制前先读revision；冲突后重新读取，禁止last-write-wins。任务ID保持匿名哈希。可视化只调用相同只读Service，不能复制控制文件、Session、任务正文或记忆内容。旧9465 API不得作为新适配器依赖。

## 9. 独立高风险出口

高风险出口不是一个可被 Codex 随意调用的普通工具。它应采用：

```text
Codex 生成计划与本地证据
→ Foursday 固定策略分类
→ 用户在独立任务明确授权目标/动作/版本
→ 执行器重新读取当前状态
→ 执行
→ 目标系统精确回读
→ 返回审计凭据
```

授权必须绑定不可变提交、目标环境、动作参数和有效期，不能使用聊天中的“好的”“继续”推断生产权限。

## 10. 测试要求

每个扩展至少覆盖：

| 测试类 | 示例 |
|---|---|
| 正向 | 唯一身份、唯一项目、成功读取/发送/回读 |
| 身份反向 | ID 缺失、ID 不匹配、跨租户、显示名碰撞 |
| 权限反向 | 陌生人、未@群聊、未注册项目、跨CWD、过期Token |
| 输入边界 | 空值、最大长度、分页、附件、乱序、重复 |
| 副作用 | 幂等、失败前、部分成功、unknown、重启后恢复 |
| 并发 | 同会话投递串行、Codex子Agent并行、ownerRevision/sendGeneration接管竞态 |
| 安全 | 提示注入、秘密、路径穿越、符号链接、环境泄漏 |
| 运维 | 安装、配置漂移、健康检查、停止、回滚 |

真实平台验收只能使用合成或已授权测试数据，不能把真实消息/身份提交到仓库 fixture。

## 11. 贡献步骤

1. 在 PRD 中确认能力属于 P0/P1/P2 及非目标边界。
2. 选择 Connector、Skill、MCP、Context Provider 或独立出口之一。
3. 写最小契约与威胁模型，再写实现。
4. 添加正向、拒绝、失败、重复、重启和回读测试。
5. 更新技术设计中的模块映射和本指南的平台表。
6. 运行 JavaScript/Python/安装/安全门禁。
7. PR 正文说明权限、数据、失败语义、回滚与未覆盖项。
