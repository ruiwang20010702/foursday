# 消息实时性人工验收模板

> 用于Foursday消息实时性候选。部署前填写目标完整SHA、DWS版本和测试时间；不要写联系人真实ID、消息正文、token或私人项目内容。

## 1. 前置状态

| 项目 | 预期 | 实际 |
|---|---|---|
| 目标SHA | 本地、远端、Profile一致 |  |
| DWS版本 | `v1.0.59+` |  |
| Gateway | `ready=true` |  |
| 事件入口 | `eventWakeReady=true` |  |
| 降级状态 | `eventWakeDegraded=false` |  |
| 文件兜底 | 保留 |  |
| 定时兜底 | 30000毫秒 |  |
| 出站稳定 | 基础8000、最大20000毫秒 |  |
| 发送范围 | 仅既有allowlist |  |

事件未ready时只能测试降级链，不能判定“实时入口通过”。

## 2. 统一停止条件

出现以下任一情况立即暂停Foursday并保存脱敏证据：

- Hermes内部英文提示进入聊天；
- 一次输入产生重复或自循环回复；
- 后续碎片到达后旧答案仍然发送；
- 回复发到错误会话；
- 出现秘密、私人路径或跨项目正文；
- Gateway不健康或事件进程反复重启。

## 3. L01 单条消息分段延迟

发送一条无需工具的低风险消息，记录：

| 阶段 | 时间 | 耗时 |
|---|---|---:|
| 消息创建 |  |  |
| Foursday发现 |  |  |
| 输入合并完成 |  |  |
| Agent开始/完成 |  |  |
| 发送开始/回读 |  |  |
| 钉钉可见 |  |  |

通过标准：Stream消息发现应显著低于30秒兜底；只出现一条最终回复。模型长尾单独记录，不能归因给消息入口。

## 4. L02 5—8秒碎片消息

连续发送三条组成同一目标的消息，相邻间隔分别控制在5—8秒：

```text
【L02-1】帮我核对当前项目
```

```text
【L02-2】只检查版本和运行状态
```

```text
【L02-3】不要修改文件，也不要重启服务
```

通过标准：

- 三条消息进入同一会话和项目；
- 最终只发送一条自然回复；
- 旧generation未进入发送账本；
- 最终答案包含第二、三条约束；
- 无busy/redirect/interrupt提示。

任一间隔不在5—8秒时记为无效并重测。

## 5. L03 人工接管竞态

可信测试联系人发送一个预计执行30秒以上的只读任务；负责人在Agent完成前人工回复并声明接管。

通过标准：后台可以继续核对，但旧AI答案不得发送；状态中介入事件只有一次，没有晚到回复。

## 6. L04 重启恢复

通过正式维护入口重启Gateway，不杀进程、不删除检查点。

通过标准：

- 重启后事件重新ready；
- 没有旧消息重放；
- 新消息仍由Stream唤醒；
- 单一Gateway、单一DWS事件消费者；
- allowlist、群聊、计划、记忆和发送开关保持不变。

## 7. L05 降级链

只在Shadow或隔离环境执行，不在Active生产中人为断网。

通过自动化或受控Shadow验证：事件命令不可用/ready失败时，状态显示`eventWakeDegraded=true`，文件事件和30秒兜底仍能发现allowlist消息，且不会扩大读取或发送范围。
